# AGENTS.md — Codex Operating Context For This Repo

This repo is for Blake's post-Landtrack business search. Any agent working here should optimize for evidence-backed niche selection, not coding speed.

## Mission

Help choose and validate one software business path that can reach $5–15k MRR for a solo founder (nights/weekends) using a 2-week discovery sprint before building.

## Non-negotiables

- Treat Landtrack as commercially dead. Do not propose resurrection paths based on obituary data.
- Avoid legally questionable data sources or scraping patterns.
- No enterprise-heavy motions that require constant high-touch sales.
- No generic "AI wrapper" ideas with no niche wedge.
- Do not encourage coding before discovery evidence exists.

## Discovery workflow defaults

1. Pick two candidate niches.
2. Run 8–10 discovery calls per niche (16–20 total).
3. Do not pitch on calls. Map workflow, pain, current tools, and existing spend.
4. Ask for referrals every call.
5. Score niches on pain intensity, willingness-to-pay signals, channel access, and personal 2-year interest.
6. Choose one niche and commit six months.

## Cold outreach rules

- Goal: book a 15-minute research call (not sell product).
- Keep initial messages short and personalized (<100 words).
- Send enough outbound volume; cold response rates of ~1–5% are normal.
- Use email + LinkedIn in parallel when possible.
- Use two follow-ups max, then stop.
- Iterate copy every 5–10 sends based on response data.
- No attachments and no marketing-style signatures.

## Idea quality filter

Apply all six checks:
1. Is someone paid ~$15–50/hr to do this now?
2. Can software/AI do ~80% with workflow UX as moat?
3. Is there one reachable niche/channel?
4. Can MVP ship in ~6 weeks?
5. Will incumbents absorb this as a feature quickly?
6. Can Blake stay interested for 2 years?

## Category guidance

- For trade-business software, think FSM/job-management + vertical logic.
- Avoid ERP framing for 1–10 person operators.
- Avoid pure CRM framing unless explicitly validated by users.

## Documentation requirements

- CRITICAL RULE: this repo is the active brainstorming workspace and source of truth for finding the next idea to build. As work progresses, update the relevant docs immediately in the same session.
- Session startup rule: before proposing ideas or plans, review `CLAUDE.md` plus key context docs in `01-strategy/` (at minimum `decisions-log.md` and `collaboration-playbook.md` if they exist) so recommendations use current context.
- Question cadence default: ask relevant strategy/discovery questions one at a time unless Blake explicitly requests a batch.
- Persist outcomes to repo files; do not rely on session memory.
- Log strategic decisions with date, rationale, and next action in `01-strategy/decisions-log.md`.
- Keep files concise and split long docs rather than growing monoliths.
